# Kurumi

Kurumi 是一个适用于 Minecraft Forge 1.8.9 的纯客户端直线方块放置辅助模组。

它的目标不是控制玩家移动或自动寻找任意搭建位置，而是让玩家在保持真实视角控制的前提下，快速、连续地放置一条平行于坐标轴的方块直线。

当前版本：**1.0.20**

仓库只发布两个版本：

- **1.0.20**：当前最新版，加入缺口优先队列与一格单步前视。
- **1.0.14.1**：结构更简单的稳定基线版本。

## 安装

1. 安装 Minecraft 1.8.9 和 Forge 11.15.1.2318。
2. 从仓库的 [Releases](https://github.com/Bomethub/Kurumi/releases) 页面下载 JAR。
3. 将 JAR 放入对应实例的 `mods` 文件夹。
4. 删除其他 Kurumi 版本，避免重复加载。

Kurumi 是客户端模组，不需要安装在服务器上。使用前请确认目标服务器的规则允许此类辅助功能。

## 使用方法

同时满足以下条件时进入 StraightLine（SL）状态：

- 主手持有可放置的完整立方体方块；
- 鼠标左键和右键同时按下。

任意条件不再满足时立即退出 SL，例如松开任意鼠标键、切换到非完整方块或手中方块耗尽。

## StraightLine 行为

### 1. 建立初始参照

每次进入 SL 时，Kurumi 都会清除上一次 SL 留下的方向、起点和面信息。

随后，模组记录准星在原版可达距离内首次命中的有效碰撞面，并将其定义为 **X 面**；X 面所属的方块位置定义为 **Y 方块**。如果进入 SL 的瞬间准星已经命中有效面，则直接采用该面，无需重新移开准星。

这里记录的是方块实际碰撞箱上的面，而不只是方块格的外轮廓。因此，半砖、楼梯等具有有效碰撞面的非完整方块可以成为 Y 方块；草、花等没有适用碰撞面的方块不会成为有效初始目标。

### 2. 识别首次经过的棱

确定 X 面后，Kurumi 会持续计算玩家视线在 X 面所在平面上的投影轨迹。

当投影轨迹第一次接近或跨过 X 面边界时，模组确定轨迹首先经过的那条棱。以组成 X 面的同一碰撞箱为基准，与 X 面沿该棱相邻的另一个面定义为 **Z 面**。

这一步只用于确定直线的方向，不会扩大实际放置距离。即使方向判定使用了 X 面所在平面的延伸区域，后续方块仍必须通过可执行的放置条件检查。

### 3. 确定 SL 方向和起点

Kurumi 首先判断 Z 面对于玩家是否在几何上可观察。该判断只考虑：

- 玩家眼睛是否位于 Z 面朝外的一侧；
- Z 面是否被 Y 方块自身的其他碰撞部分完全覆盖。

此时不考虑相邻方块对 Z 面的覆盖。根据判断结果，方向和起点按以下规则确定：

- 如果 Z 面在几何上不可观察，则将 X 面的朝外方向设为 **SL 方向**，并将 Y 方块设为 **起点方块**。
- 如果 Z 面在几何上可观察，则将 Z 面的朝外方向设为 **SL 方向**，然后检查 Z 面是否被紧邻它的方块完全覆盖：
  - 未被完全覆盖时，将 Y 方块设为起点方块。
  - 被完全覆盖时，Kurumi 会把“建立起点”作为最高优先级的自动放置任务。只要 X 面仍然提供合法的原版放置机会，模组就会自动通过 X 面向其外侧相邻方块格放置一个方块；放置成功后，新方块的位置成为起点方块。

上述起点方块的建立由 Kurumi 自动完成，不需要玩家另外手动放置。在这次自动起点放置成功前，普通的直线放置不会开始。

### 4. 沿正向轴线放置

SL 方向必定是六个坐标轴方向之一。起点方块和 SL 方向共同定义一条离散的正向射线：

```text
目标位置 = 起点方块 + n × SL方向，n = 1, 2, 3, ...
```

起点本身不属于后续目标位置。

此后，Kurumi 会根据当前命中的支撑方块、点击面和点击点计算原版右键将要放置到的方块格。只有该方块格严格位于上述正向射线上时，它才会成为放置候选；偏离射线、位于起点反方向或与起点不共线的位置都会被忽略。

实际执行前，模组还会检查手持方块、支撑方块、目标格、玩家碰撞和当前视线方向等条件。通过检查后，放置由 Minecraft 的原版右键方法完成，并执行挥手动作。SL 活跃期间会持续清除右键放置延迟（FastPlace），但每个客户端 tick 最多只进行一次真实放置尝试。

## 1.0.20 的连续性优化

- 最多保存三个短期候选，并优先处理距离起点最近的缺口。
- 多次命中同一目标时，更新为最新的真实点击点。
- 必须先放置的 X 面起点拥有最高优先级。
- 缓存候选失效后，会立即检查当前真实命中，避免无意义地浪费整个 tick。
- 加入一格单步前视：
  - 如果待放置方块尚未出现在客户端世界中，Kurumi 可以检查该方块出现后会提供的下一个面；
  - 前视仍使用玩家当前真实视线、原版方块距离和实际射线交点；
  - 前视只跨越一个尚未放下的依赖方块，不会递归生成整条放置链。

## 执行时序与限制

- `RenderTick.END` 只捕获视线和几何候选。
- `PlayerTick.START` 才会执行真实右键。
- 每个客户端 tick 最多进行一次真实放置尝试。
- 不改变本地视角。
- 不发送独立或静默旋转。
- 不搜索周围支撑方块。
- 不使用 fallback 补放。
- 不在同一 tick 内连续放置多个目标。
- 候选只短期有效，执行前会重新检查手持方块、支撑方块、目标格、碰撞、距离和视线方向。

如果玩家在一个客户端 tick 内扫过超过一个尚未出现的连续依赖面，仍可能达到单步前视和单 tick 放置次数的上限。

## 从源码构建

需要：

- JDK 8
- Gradle 2.14.1
- 可访问 Forge/Minecraft 依赖下载源

```text
gradle setupDecompWorkspace
gradle build
```

构建结果位于 `build/libs/`。

源码使用 Forge 1.8.9、ForgeGradle 2.1 和 MCP stable 22 映射。
